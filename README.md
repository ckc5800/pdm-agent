# pdm-agent

![CI](https://github.com/ckc5800/pdm-agent/actions/workflows/ci.yml/badge.svg)

설비 센서 시계열에서 이상을 탐지하고, LLM이 정비 진단 리포트를 생성하는
예지보전(Predictive Maintenance) 데모이다.

음성 AI 분야에서 실시간 신호를 다루어 온 경험을 산업 설비 도메인에
적용하기 위해 제작하였다. 진동 RMS와 음성 파형 모두 시계열에서 이상
패턴을 탐지하는 문제라는 점에서 골격이 동일하다.

## 설계 원칙: 탐지는 결정적 알고리즘이 담당한다

```
시뮬레이터 ──▶ 이상 탐지 (결정적 알고리즘) ──▶ LLM 진단 (해석·권고만)
 결함 주입      z-score / EWMA / 추세+RUL        탐지 근거 밖 수치 생성 금지
```

이상 탐지는 재현 가능해야 하며 동일 입력에 대해 항상 동일한 결과를
보장해야 한다. 따라서 탐지는 통계/신호처리 알고리즘이 수행하고, LLM은
탐지 근거를 종합하여 사람이 읽을 진단(원인 추정·심각도·권고 조치)을
작성하는 역할만 담당한다. 프롬프트에서 "근거에 있는 수치만 사용"하도록
제한하여 hallucination을 차단하였다.

## 탐지기 구성

| 탐지기 | 대상 | 방법 |
|---|---|---|
| z-score | 순간 충격 (낙하물, 이물질) | rolling window 기준 z > 5 스파이크 |
| EWMA | 지속적 수준 이탈 (과열 등) | 초기 구간 기준선 + 4σ 관리한계 초과 |
| 추세 | 점진적 열화 (베어링 마모) | 선형회귀 기울기 + 한계치 도달 시간(간이 RUL) 추정 |

시뮬레이터는 회전기계를 단순화한 모델로, 8시간 주기 부하 변동 위에
결함 3종(순간 충격, 점진적 베어링 마모, 일시 과열)을 주입한다.
주입 시점이 ground truth로 기록되어 탐지기의 정량 평가에 사용된다.

## 실행

```bash
pip install -r requirements.txt   # httpx 하나 (탐지기는 표준 라이브러리만 사용)

# 탐지기 평가 (LLM 불필요, 바로 실행됨)
python eval.py

# E2E 데모 — LLM 진단까지 (Ollama + qwen2.5:3b 필요)
python run_demo.py
# 결과: results/report.md, results/chart.svg

# NASA C-MAPSS 검증 — FD001~FD004 통합 CLI
python eval_cmapss.py --fd FD001 --model exp           # train 프로토콜
python eval_cmapss.py --fd FD004 --select-sensors --smooth 5   # 전처리 적용 (권장)
python eval_cmapss.py --fd FD001 --split test --smooth 5       # 공식 test 셋

# 단위 테스트 (합성 C-MAPSS 데이터로 평가 파이프라인까지 검증, 실데이터 불필요)
pip install -r requirements-dev.txt
python -m pytest -q
```

## 평가 결과 (시뮬레이터)

seed를 달리한 5개 시나리오에서 주입 결함 15건을 전부 탐지하였으며
오탐은 없었다.

```
결함 재현율: 100% (15/15), 총 오탐: 0건
```

단, 이는 **탐지기를 본 시뮬레이터의 결함 모델에 맞추어 튜닝한 통제
실험**이다. 실제 설비 데이터는 결함 모드가 훨씬 다양하고 라벨이 없어
동일한 수치를 기대할 수 없다. 본 데모의 목적은 "탐지 → 근거 전달 →
LLM 진단" 파이프라인의 구조를 보이는 데 있다.

LLM 진단 출력 예시 (qwen2.5:3b):

> 진동이 지속적으로 증가하고 있으며, 이와 함께 온도도 상승 추세를 보이고
> 있습니다. 이러한 현상은 베어링 마모 또는 윤활 불량을 의심할 수 있습니다.
> 따라서 정기적인 점검 및 윤활 재공급이 필요하며...

탐지 근거(진동 상승 + 온도 동반 상승)로부터 타당한 원인 후보를 제시하였다.

## 실데이터 검증: NASA C-MAPSS

시뮬레이터 결과는 자체 제작한 문제를 자체 채점한 것이므로, 동일한
탐지기를 공개 벤치마크인 NASA C-MAPSS에 적용하여 검증하였다. FD001은
터보팬 엔진 100대를 고장까지 운전한 run-to-failure 시계열이다.

```bash
# 데이터: NASA PCoE 저장소에서 받아 data/raw/cmapss/에 압축 해제 (~12MB)
# https://phm-datasets.s3.amazonaws.com/NASA/6.+Turbofan+Engine+Degradation+Simulation+Data+Set.zip
python eval_cmapss.py --fd FD001 --k 3.0 --model linear
```

프로토콜: 열화 추세가 알려진 센서 10개에 EWMA 관리한계 탐지기를 그대로
적용하고, 서로 다른 센서 2개가 이탈한 경우에만 엔진 경보로 인정하였다.
RUL은 엔진 1~50의 고장 시점 센서값으로 한계치를 보정하고 엔진 51~100
에서만 평가하여 라벨 누수를 차단하였다.

**경보 성능 — 관리한계 kσ 트레이드오프:**

| k | 고장 전 경보 | 리드타임 중앙값 | 수명 초반 30% 조기 경보 |
|---:|---:|---:|---:|
| 4.0σ (합성 튜닝값) | 63/100 | 22 사이클 | 0 |
| 3.5σ | 82/100 | 24 사이클 | 0 |
| 3.0σ | 94/100 | 30 사이클 | 0 |
| 2.5σ | 99/100 | 37 사이클 | 0 |
| 2.0σ | 100/100 | 48 사이클 | 0 |

주요 관찰은 다음 세 가지이다.

1. **합성 데이터에서 튜닝한 4σ는 실데이터에서 지나치게 보수적이었다**
   (63/100). 3σ로 완화하면 94/100이 되며 조기 경보는 여전히 0건이다 —
   지속성 필터(10사이클)와 2센서 투표가 노이즈를 이미 제거하고 있어
   k를 낮출 여지가 있었다.
2. **k=2.0에서도 조기 경보가 0건인 것은 데이터셋 특성에 기인한다.**
   FD001은 모든 엔진이 단조 열화하며 건강한 상태로 종료되는 엔진이
   없어 전통적인 오탐율을 측정할 수 없다. 이에 "수명 초반 30% 내
   경보"를 조기 경보의 대리 지표로 사용하였다. 건강한 채 종료되는 운전
   데이터가 있는 경우 낮은 k 구간의 결과는 달라질 수 있다.
3. **선형 외삽 RUL은 horizon이 길어질수록 성능이 저하된다.** 고장
   30사이클 전 시점의 RUL 추정은 MAE 28.5 사이클(중앙값 오차 24),
   50사이클 전은 MAE 58.8이다. C-MAPSS의 열화는 후반부로 갈수록
   가속하는 곡선이어서, 최근 30사이클의 선형 기울기는 잔여 수명을
   과대평가한다.

### 지수 열화 모델 (`--model exp`)

기준선 대비 편차 d(t)가 지수적으로 증가한다고 가정하고 ln(d)에
선형회귀를 적용하면, 한계 편차 도달 시점이 닫힌식으로 도출된다.

| RUL 모델 | @30사이클 전 | @50사이클 전 |
|---|---|---|
| 선형 외삽 | MAE 28.5 (50/50대 추정) | MAE 58.8 (50/50대) |
| 지수 모델 | **MAE 12.9** (48/50대) | **MAE 23.4** (35/50대) |

오차가 절반 이하로 감소하였다. 다만 지수 모델은 편차가 기준선 위로
충분히 상승하지 않은 엔진에 대해 추정을 보류한다(50사이클 전 기준
35/50대만 응답). 응답 정확도와 응답률 간의 트레이드오프이며, 오추정보다
보류가 안전한 정비 계획 관점에서는 실용적인 특성으로 판단된다.

> **이 MAE를 절대 성능으로 읽으면 안 된다.** 본 프로토콜은 "고장 정확히
> 30(또는 50) 사이클 전" 시점에서 질문하므로 정답이 모든 엔진에서
> 상수이다(검증: 정답 집합 {30}, 표준편차 0.0). 따라서 **항상 30만
> 출력하는 예측기가 MAE 0.0을 받는다.** 이 지표가 잴 수 있는 것은 고정
> horizon에서의 캘리브레이션뿐이며, 다양한 RUL을 구분하는 능력은 재지
> 못한다. 위 표는 선형과 지수를 **동일 조건에서 상대 비교**한 값으로만
> 유효하다. 실제 변별력은 라벨이 6~195로 분포하는 아래 공식 test 셋에서
> 평가해야 한다.

### FD002 — 운전 조건 6개 (`--fd FD002`)

FD002는 고도/마하수가 상이한 운전 조건 6개를 오가며 운전된 260대
데이터이다. 조건 전환 시 센서 절대값이 열화와 무관하게 크게 변동하므로,
동일 탐지기를 그대로 적용하면 **경보가 한 건도 발생하지 않는다
(0/130)** — 조건이 혼합된 기준선의 표준편차가 부풀어 관리한계가 도달
불가능한 수준으로 상승하기 때문이다.

조건별 z-정규화 적용 시 성능이 회복된다. 정규화 통계는 보정 엔진
(전반 130대)에서만 계산하고 지표는 평가 엔진(후반 130대)에서만
측정하여 누수를 차단하였다.

| | 정규화 없음 | 조건별 z-정규화 |
|---|---:|---:|
| 고장 전 경보 (3σ) | 0/130 | 104/130 (조기 경보 0) |
| RUL@30 (지수 모델) | — | MAE 23.7 (109대 추정) |
| RUL@50 (지수 모델) | — | MAE 29.2 (57대 추정) |

단일 조건인 FD001(94/100) 대비 낮은 수치이다 — 조건 전환 노이즈가
잔존하며, FD002 자체가 더 어려운 데이터셋이다. 선형 RUL은 여기서도
지수 모델 대비 열세였다 (MAE 28.5/51.6 vs 23.7/29.2).

### FD003/FD004 — 전 데이터셋 확장 (`--fd FD003|FD004`)

FD003은 결함 모드 2개(HPC 열화 + 팬 열화, 단일 조건), FD004는 조건
6개 + 결함 모드 2개로 가장 어려운 조합이다. FD004에는 FD002의 조건별
z-정규화를 그대로 재사용하였다. 네 데이터셋을 동일 프로토콜(k=3.0,
지수 RUL)로 비교하면 다음과 같다.

| 데이터셋 | 조건·모드 | 고장 전 경보 | 리드타임 중앙값 | RUL@30 | RUL@50 |
|---|---|---:|---:|---|---|
| FD001 | 1·1 | 94/100 | 30 | MAE 12.9 (48/50대) | MAE 23.4 (35/50대) |
| FD003 | 1·2 | 96/100 | 32 | MAE 14.8 (48/50대) | MAE 30.2 (30/50대) |
| FD002 | 6·1 | 104/130 | 22 | MAE 23.7 (109/130대) | MAE 29.2 (57/130대) |
| FD004 | 6·2 | 101/125 | 28 | MAE 22.3 (116/125대) | MAE 33.4 (77/125대) |

분모 유의: 다중 조건 셋(FD002/FD004)은 정규화 통계 보정에 사용한
전반부를 제외한 평가 엔진에서만 측정한 값이다(FD002 260대 중 130대,
FD004 249대 중 125대). 단일 조건 셋의 경보는 엔진별 자체 기준선만
사용하므로 전체 엔진에서 측정하였다.

이전 버전에서는 "결함 모드 구분 없이 단일 한계치를 사용하는 현재
구조로는 FD004 성능이 더 낮을 것"으로 예상하였으나, 결과는 달랐다.
난이도를 지배하는 축은 결함 모드 수가 아니라 운전 조건 수이다
(FD001→FD003은 유지, FD001→FD002는 하락). 결함 모드가 상이해도 본
센서 10개가 포착하는 것은 공통적인 효율 저하이므로, 모드 구분 없는
단일 한계치로도 경보·RUL이 유지된 것으로 해석된다.

### Health index 센서 융합 (`--fuse`)

센서 10개를 각각 초기 30사이클 기준으로 z-정규화한 후 평균하여 단일
지표로 융합한다. 방향은 로더에서 이미 통일되어 있으므로 평균만으로
융합이 성립하며, 개별 센서 노이즈가 1/√10로 감소하여 지수 모델이
편차를 더 이른 시점부터 신뢰할 수 있다. 경보 역시 융합 지표 하나로
측정한다(투표 불필요).

| (k=3.0, exp) | 경보 | 리드타임 | RUL@30 MAE | RUL@50 MAE |
|---|---:|---:|---|---|
| FD001 | 94 → **100**/100 | 30 → **68** | 12.9 (48대) → **10.9 (50/50대)** | 23.4 (35대) → **14.9 (46/50대)** |
| FD002 | 104 → **130**/130 | 22 → **50** | 23.7 (109대) → **11.5 (126/130대)** | 29.2 (57대) → **21.0 (101/130대)** |
| FD003 | 96 → 56/100 | 32 → 70 | 14.8 (48대) → 18.1 (30/50대) | 30.2 (30대) → 23.8 (28/50대) |
| FD004 | 101 → 73/125 | 28 → 56 | 22.3 (116대) → 19.3 (70/125대) | 33.4 (77대) → 28.9 (54/125대) |

단일 결함 모드(FD001/FD002)에서는 전 지표가 일제히 개선되었다 — 경보
100%, 리드타임 2배 이상, RUL 오차·보류율 동시 감소. 반면 결함 모드가
2개인 FD003/FD004에서는 경보가 절반 수준으로 하락하였다. 평균 융합은
"센서 10개가 동일 방향으로 함께 움직인다"는 가정에 의존하는데, 결함
모드별로 센서 시그니처가 상이하면 반응하지 않는 센서들이 신호를
희석하기 때문이다. 즉 융합의 이득은 이 가정이 성립하는 범위에서만
유효하다. FD003/FD004의 리드타임 수치(70/56)는 경보에 성공한 엔진에 한정된
값이므로 해석에 유의해야 한다. 모드별 센서 부분집합으로 지표를
분리하는 것이 다음 단계이다.

## 전처리 개선: 평활과 데이터 기반 센서 선택

여기까지의 전처리는 사실상 "부호 통일 + 조건별 z-정규화"뿐이었고 노이즈
처리가 없었다. 지수 모델은 30사이클 창에서 ln(d)를 적합하는데, 이 창에
노이즈로 인한 하강이 한 번만 섞여도 `min(d) <= 0`에 걸려 추정을 보류한다.
보류율이 높았던 원인이 열화 부재가 아니라 노이즈일 수 있다는 가설이다.

### 후행 이동평균 (`--smooth N`)

적합 전에 이동평균으로 노이즈를 줄인다. **반드시 후행(causal)이어야
한다** — 중심 이동평균을 쓰면 t 시점의 평활값이 t 이후 관측을 포함해
"t까지만 보고 추정한다"는 전제가 깨진다. 단위 테스트로 인과성을 고정했다.

경보(train 프로토콜, k=3.0)에서 효과가 가장 뚜렷하다.

| 셋 | 기준 | `--smooth 5` | `--select-sensors --smooth 5` |
|---|---|---|---|
| FD001 | 94/100 (리드 30) | **100/100 (72)** | 100/100 (92) |
| FD002 | 104/130 (22) | **130/130 (61)** | 130/130 (74) |
| FD003 | 96/100 (32) | **100/100 (73)** | 100/100 (100) |
| FD004 | 101/125 (28) | **125/125 (66)** | 125/125 (94) |

**네 데이터셋 모두 경보 100%에 도달했고 리드타임이 2~3배가 되었으며,
조기 경보(수명 초반 30%)는 전 구성에서 0을 유지한다.** 놓치던 엔진은
열화가 없어서가 아니라 노이즈에 묻혀 있었던 것이다.

### MAE가 아니라 대조군 마진으로 읽어야 한다

test 셋 RUL에서는 해석에 주의가 필요하다. 평활을 넣으면 **MAE는 오히려
올라간다**(FD001 13.4 → 15.8). 응답률이 41%에서 75%로 뛰면서 그동안
포기하던 어려운(수명이 많이 남은) 엔진들이 채점 대상에 들어오기
때문이다. 앞서 세운 원칙대로 같은 응답 집합의 상수 대조군과 함께 보면
방향이 분명해진다.

| (exp, 125캡, 비융합) | 응답률 | MAE | 상수 대조군 | 마진 |
|---|---:|---:|---:|---:|
| FD001 기준 | 41/100 | 13.4 | 19.7 | −6.3 |
| FD001 `--smooth 5` | 75/100 | 15.8 | 35.7 | **−19.9** |
| FD002 기준 | 91/259 | 15.2 | 14.3 | **+0.9 (패배)** |
| FD002 `--smooth 5` | 169/259 | 18.6 | 33.1 | **−14.5** |
| FD003 기준 | 43/100 | 19.0 | 21.5 | −2.5 |
| FD003 `--select-sensors --smooth 5` | 86/100 | 17.8 | 33.2 | **−15.4** |
| FD004 기준 | 94/248 | 17.8 | 19.6 | −1.8 |
| FD004 `--select-sensors --smooth 5` | 192/248 | 23.0 | 40.7 | **−17.7** |

앞 라운드에서 상수 예측기에 지던 FD002가 +0.9에서 −14.5로 뒤집혔고,
마진이 2 사이클 이하로 애매하던 FD003·FD004도 −15 안팎으로 벌어졌다.
**MAE만 봤다면 "평활은 성능을 악화시킨다"고 결론 냈을 실험이다.**

창 크기는 5~7이 가장 좋았다(FD001 마진 −19.9/−20.0, FD004 −13.1/−13.1).
10 이상에서는 지연이 커져 마진이 다시 줄고, 선택과 함께 쓰면 조기 경보가
1~2건 발생하기 시작한다. 기본값은 평활 없음(`--smooth 1`)으로 두어 이전
수치가 그대로 재현되게 하고, 권장 구성은 아래에 따로 적는다.

### 데이터 기반 센서 선택 (`--select-sensors`)

기존 센서 10개는 FD001 문헌에서 가져온 고정 목록이었다. 보정 엔진에서
사이클과의 상관을 재어 |r| ≥ 0.4인 센서와 그 부호를 직접 고르게 했다
(평가 엔진이 섞이면 센서 선택 자체가 누수이므로 보정 엔진만 사용).

| 셋 | 선택 결과 | 고정 목록 대비 |
|---|---|---|
| FD001 / FD002 / FD003 | 14개 | **+s8, s9, s13, s14** |
| FD004 | 10개 | +s8, s9, s13, s14 / −s7, s12, s20, s21 |

고정 목록은 강한 신호 4개를 통째로 빠뜨리고 있었다. FD004에서는 이
넷이 상위권(|r| 0.72~0.82)인 반면 제외된 s7·s12·s20·s21은 0.30~0.33에
불과하다. 효과는 데이터셋 성격에 따라 갈린다 — 결함 모드가 2개인
FD003(−9.6 → −15.4)과 FD004(−13.1 → −17.7)에서는 뚜렷이 개선되지만,
FD001(−19.9 → −16.9)과 FD002(−14.5 → −9.2)에서는 오히려 나빠진다.
**고정 목록이 FD001 기준으로 만들어졌으니, 그 목록이 안 맞는
데이터셋에서만 이득이 나는 것이 앞뒤가 맞는다.**

### 부수 발견: 평활이 센서 융합을 대체한다

앞서 도입한 health index 융합은 개별 센서 노이즈를 1/√10로 줄이는 것이
목적이었다. 그런데 시간축 평활을 넣고 나면 융합은 오히려 손해다.

| (exp, 125캡) 마진 | 융합, 평활 없음 | 비융합, `--smooth 5` |
|---|---:|---:|
| FD001 | −16.2 | **−19.9** |
| FD002 | −7.0 | **−14.5** |
| FD003 | +0.4 | **−9.6** |
| FD004 | −3.9 | **−13.1** |

네 데이터셋 전부 평활 쪽이 낫다. **융합은 노이즈 제거의 조잡한 대용품
이었고, 그 대가로 센서 간 다양성과 투표 능력을 잃고 있었다.** 융합이
FD003/FD004에서 경보를 반토막 냈던 이유도 같은 맥락으로 설명된다 —
결함 모드마다 다른 센서가 반응하는데 평균이 그것을 뭉갠 것이다.

### 권장 구성

```bash
# 단일 결함 모드 (FD001, FD002): 평활만
python eval_cmapss.py --fd FD001 --smooth 5

# 결함 모드 2개 (FD003, FD004): 평활 + 데이터 기반 센서 선택
python eval_cmapss.py --fd FD004 --select-sensors --smooth 5
```

이 구성에서 경보는 네 셋 모두 100%(조기 경보 0), RUL은 상수 대조군 대비
−14 ~ −20 사이클의 마진을 확보한다. 기본값을 바꾸지 않은 이유는 위
문서의 모든 수치를 재현 가능하게 유지하기 위해서다.

## 공식 test 셋 평가 (`--split test`)

앞의 train 프로토콜은 자체 설계이므로 문헌 수치와 직접 비교할 수 없다.
공식 test 셋은 각 엔진이 고장 전 임의 시점에서 절단되어 있고 해당
시점의 실제 RUL 라벨(`RUL_FDxxx.txt`)이 제공되므로, 문헌의 RMSE/PHM08
score와 동일한 조건이다. train 전체로 한계치(및 FD002/FD004의 정규화
통계)를 보정하고, test 각 엔진의 마지막 사이클에서 RUL을 추정하여
라벨과 비교하였다.

전제할 차이점: 본 추정기는 열화가 관측되지 않으면 추정을 보류한다.
라벨이 RUL 6~195 사이클까지 분포하는데 수명 중반의 엔진에는 열화 신호
자체가 없어, 응답률이 24~61%에 그친다. 따라서 아래 수치는 열화가
관측된 엔진에 한정된 성능이며, 전수 응답하는 학습 기반 모델과의 직접
비교에는 적합하지 않다.

부분집합에 매긴 점수는 그 자체로는 해석이 불가능하다. 그래서 **동일한
응답 집합에 "항상 그 집합의 라벨 중앙값"을 출력하는 상수 예측기**를
함께 돌려 대조군으로 삼았다. 상수를 못 이긴다면 그 MAE는 추정 능력이
아니라 집합 선택의 산물이다.

| test 셋 (exp, 추정 125캡) | 응답률 | MAE | RMSE | 상수 대조군 MAE | 판정 |
|---|---:|---:|---:|---:|:--|
| FD001 | 41/100 | 13.4 | 20.9 | 19.7 | 이김 (−6.3) |
| FD001 `--fuse` | 61/100 | 14.6 | 19.5 | 30.8 | 이김 (−16.2) |
| FD002 | 91/259 | 15.2 | 24.3 | 14.3 | **못 이김 (+0.9)** |
| FD002 `--fuse` | 128/259 | 18.6 | 25.3 | 25.6 | 이김 (−7.0) |
| FD003 | 43/100 | 19.0 | 28.0 | 21.5 | 이김 (−2.5) |
| FD003 `--fuse` | 29/100 | 21.8 | 25.8 | 21.4 | **못 이김 (+0.4)** |
| FD004 | 94/248 | 17.8 | 27.1 | 19.6 | 이김 (−1.8) |
| FD004 `--fuse` | 59/248 | 15.0 | 19.1 | 18.9 | 이김 (−3.9) |

**8개 설정 중 2개에서 추정기가 상수 예측기에 졌다.** 이긴 경우에도
FD003·FD004 비융합은 마진이 2 사이클 안팎으로, 통계적 우위라 부르기
어렵다. 뚜렷한 우위는 FD001(특히 융합, −16.2)에 한정된다. 참고로 같은
상수를 전체 엔진에 적용하면 MAE가 35.8~46.5로 뛰므로, 위 대조군 수치가
낮다는 것 자체가 응답 집합이 얼마나 쉬운 쪽으로 치우쳤는지를 보여준다.

**문헌 대비 위치.** FD001 test 셋에 보고된 RMSE는 학습 기반 모델 기준
다음과 같다. 이들은 모두 100대 전수에 응답한 결과이며, 학습 시 RUL
타깃을 125 내외로 캡하므로 본 표의 캡 적용 수치와 비교 조건이 같다.

| 방법 | FD001 test RMSE | 확인한 출처 |
|---|---:|---|
| LSTM | 14.931 | [1] Table III |
| Deep LSTM (Zheng et al. 2017) | 16.14 | [1] Table III, [2] Table 4 |
| Ridge Regression (선형) | 16.634 | [1] Table III |
| 1D CNN | 16.971 | [1] Table III |
| CNN (Babu et al. 2016) | 18.45 | [2] Table 4 |

[1] Galchar, Goel, Kanu, *Remaining Useful Life Estimation for Turbofan
Engines: A Comparative Study of Classical, CNN, and LSTM Approaches*,
[arXiv:2604.27234](https://arxiv.org/html/2604.27234v1) ·
[2] *Data-driven Prognostics with Predictive Uncertainty Estimation using
Ensemble of Deep Ordinal Regression Models*,
[arXiv:1903.09795](https://arxiv.org/pdf/1903.09795)

본 추정기의 최고 성능은 융합 적용 시 RMSE 19.5이며, 그것도 100대 중
61대에만, 그것도 쉬운 쪽으로 치우친 61대에만 응답한 결과이다. 즉
**응답률과 정확도 양쪽에서 학습 기반 모델에 뒤진다.** 특히 선형 Ridge
Regression이 전수 응답으로 16.6을 기록한다는 점은, 격차의 원인이
"딥러닝이 아니라서"가 아니라 학습 없이 외삽만으로는 한계가 있다는 데
있음을 보여준다.

본 접근의 의의는 정확도 경쟁이 아니라 **라벨과 학습 없이 즉시 배치
가능하다는 점**에 있다. 신규 설비처럼 고장 이력이 없어 지도학습이
불가능한 초기 단계에서, 조건별 정규화와 관리한계만으로 경보를 내고
열화가 뚜렷한 구간에 한해 RUL을 제시하는 용도이다.

융합의 효과는 test 셋에서도 갈린다: FD001은 응답률이 41→61%로 오르면서
오차가 유지되었고, FD004는 응답률이 하락하는 대신 응답 엔진의 오차·
score가 개선되었으며, FD002는 응답률은 오르나 MAE가 악화되었다.

### 미채택 실험: 최소 근거 센서 요건 (`--min-sensors`)

RUL 추정은 "상승 추세이고 한계치까지 여유가 있는" 센서만 골라 중앙값을
취한다. 경보는 서로 다른 센서 2개를 요구하는데(`VOTES=2`) RUL에는 그런
요건이 없어, FD001 응답 엔진의 7대는 센서 단 1개에 근거하고 있었다.
그래서 경보와 같은 방식으로 최소 근거 센서 수를 올려 보았다.

| FD001 (exp, 125캡) | 응답 | MAE | 상수 대조군 | 마진 |
|---|---:|---:|---:|---:|
| `--min-sensors 1` (현행) | 41/100 | 13.4 | 19.7 | −6.3 |
| `--min-sensors 2` | 34/100 | 9.5 | 14.7 | −5.2 |
| `--min-sensors 3` | 30/100 | 7.9 | 10.9 | −3.0 |

MAE만 보면 13.4 → 7.9로 크게 좋아진다. **그러나 상수 대조군도 19.7 →
10.9로 함께 내려가고, 마진은 오히려 −6.3 → −3.0으로 줄어든다.** 즉
개선의 정체는 추정 능력 향상이 아니라 쉬운 엔진만 남기는 선택 효과이다.
FD004에서는 min 2 이상에서 아예 상수에 지고(12.3 vs 12.1), FD002는 어느
값에서도 이기지 못한다. 따라서 **기본값은 1로 두고 채택하지 않았다.**
대조군 없이 MAE만 봤다면 정반대 결론을 내렸을 실험이라, 기록으로 남긴다.

### PHM08 score 해석 주의

PHM08 score는 늦은 예측에 지수 벌점을 부과하므로 과대추정 소수 건에
전체가 지배된다. FD001 캡 미적용 원점수 1.56×10⁹은 **그 100.0%가 단 한
대(오차 +211.7 → e²¹·¹⁷)에서 나온다**. 다음으로 큰 항은 325.4, 206.9에
불과하다. 추정치를 125 사이클로 캡하면(문헌의 piecewise-linear RUL
타깃과 동일한 발상) 779.4로 내려간다.

또한 score는 **합계라서 엔진 수에 비례**한다. 41대에 대한 합을 100대에
대한 문헌 합과 나란히 놓으면 안 되므로, JSON과 출력 모두 원점수·캡
점수와 함께 `phm08_per_engine`을 기록한다.

## 한계

- 샘플이 1분 간격 RMS이므로 주파수 영역 분석(FFT, 베어링 결함 주파수)은
  구조상 제외하였다. 원파형 데이터 확보 시 스펙트럼 탐지기를 추가할 수 있다.
- RUL은 외삽 기반 간이 추정이다. 선형 모델의 한계는 C-MAPSS 검증에서
  수치로 확인되었고, 지수 모델로 오차를 절반 이하로 줄였으나 추정
  보류율이 발생한다 — 공식 test 셋 기준 응답률 24~61%. 정비 계획에는
  보류가 안전하나, 벤치마크 전수 비교에는 학습 기반 모델이 필요하다.
- **RUL 추정 능력의 우위가 확실한 구간은 좁다.** 상수 예측기 대조에서
  8개 설정 중 2개는 패배, 2개는 마진 2 사이클 이하였다. 현재 형태로
  신뢰할 만한 것은 경보(리드타임 확보)이며, RUL 수치는 참고값으로
  다루어야 한다.
- train 프로토콜의 RUL 지표는 정답이 고정 상수(30/50)라 변별력이 없다.
  선형 대 지수의 상대 비교에만 사용하였고, 절대 성능은 공식 test 셋
  기준으로만 서술하였다.
- Health index 융합은 "센서들이 동일 방향으로 움직인다"는 단일 결함
  모드 가정에 의존한다. FD003/FD004에서 경보가 절반 수준으로 하락함을
  확인하였으며, 모드별 지표 분리는 미구현이다. 이후 평활을 도입한 뒤로는
  융합이 모든 셋에서 열세여서, 사실상 대체된 기능으로 본다.
- 평활의 최적 창 크기(5~7)는 데이터셋별로 조정한 값이 아니라 공통값이다.
  또한 평활은 지연을 유발하므로, 급격한 고장 모드(스텝형 이상)에는
  불리할 수 있다. 본 데이터셋들은 모두 점진적 열화라 이 위험이 드러나지
  않았다 — 시뮬레이터의 순간 충격 탐지에는 평활을 적용하지 않는다.
- 조기 경보 지표는 "수명 초반 30% 내 경보"라는 대리 지표다. 평활 5에서
  리드타임 중앙값이 61~73 사이클(수명의 약 30~40%)까지 늘어났는데,
  건강한 상태로 종료되는 엔진이 없는 데이터셋 특성상 이것이 과잉 경보인지
  판정할 방법이 없다. 실 운용 데이터로 재검증이 필요한 부분이다.
